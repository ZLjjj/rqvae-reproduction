## 🔄 RQVAE前向传播流程

```
输入: Embedding向量 (2560维)
  │
  ▼
┌──────────────────────────────────┐
│      MLP Encoder               │
│  [2560] → [512] → [256] → [64]  │
└────────────┬─────────────────────┘
             │
             ▼
      Latent向量 (64维)
             │
             ▼
┌────────────────────────────────────────────────────────┐
│                    Layer 1: VQ                        │
│  1. 计算latent与1024个码本的距离                        │
│  2. 选择最近的码本索引 idx_1 (0-1023)                  │
│  3. 量化向量 q_1 = codebook[idx_1]                     │
│  4. 残差 r_1 = latent - q_1                           │
│                                                        │
│  可选: Sinkhorn软分配 (L1启用时)                        │
│  可选: KMeans初始化码本                                 │
│  可选: EMA更新码本                                      │
└──────────────────┬─────────────────────────────────────┘
                   │
                   ▼
              残差 r_1 (64维)
                   │
                   ▼
┌────────────────────────────────────────────────────────┐
│                    Layer 2: VQ                        │
│  输入: r_1                                             │
│  输出: idx_2, q_2, r_2 = r_1 - q_2                    │
└──────────────────┬─────────────────────────────────────┘
                   │
                   ▼
              残差 r_2 (64维)
                   │
                   ▼
┌────────────────────────────────────────────────────────┐
│                    Layer 3: VQ                        │
│  输入: r_2                                             │
│  输出: idx_3, q_3, r_3 = r_2 - q_3                    │
└──────────────────┬─────────────────────────────────────┘
                   │
                   ▼
              残差 r_3 (64维)
                   │
                   ▼
┌────────────────────────────────────────────────────────┐
│                    Layer 4: VQ                        │
│  输入: r_3                                             │
│  输出: idx_4, q_4, r_4 = r_3 - q_4                    │
│                                                        │
│  可选: Sinkhorn软分配 (L4启用时)                        │
└──────────────────┬─────────────────────────────────────┘
                   │
                   ▼
              残差 r_4 (64维)
                   │
                   ▼
┌────────────────────────────────────────────────────────┐
│                Layer 5: HardCodeMapper                │
│  输入: saletype字段 (非向量)                            │
│  映射: "PAY" → 42, "FREE" → 49                         │
│  输出: idx_5, q_5 = codebook[idx_5]                   │
└──────────────────┬─────────────────────────────────────┘
                   │
                   ▼
        求和所有量化向量
    sum = q_1 + q_2 + q_3 + q_4 + q_5
                   │
                   ▼
┌──────────────────────────────────┐
│      MLP Decoder               │
│  [64] → [256] → [512] → [2560]  │
└────────────┬─────────────────────┘
             │
             ▼
   重构向量 (2560维)
             │
             ▼
   计算重构损失: MSE(输入, 重构)


最终输出:
  - SID索引: [idx_1, idx_2, idx_3, idx_4, idx_5]
           例如: [12, 83, 4, 701, 25]
  - SID tokens: ["<a_12>", "<b_83>", "<c_4>", "<d_701>", "<e_25>"]
  - 重构向量: 用于计算loss
```

## 🎯 Sinkhorn算法图解

```
问题: 如何让1024个码本被均匀使用?

传统VQ (硬分配):
  样本1 → 距离计算 → 最近码本: #12 ✓
  样本2 → 距离计算 → 最近码本: #12 ✓
  样本3 → 距离计算 → 最近码本: #12 ✓
  ...
  结果: 码本#12被大量使用，其他码本闲置
  L1利用率: 4.79% (只有49个码本被用)

═══════════════════════════════════════════════════════════

Sinkhorn (软分配 + 均匀化约束):

初始状态:
  Batch: 1024个样本
  Codebooks: 1024个码本

  1. 计算距离矩阵 D[i,j] = dist(sample_i, codebook_j)
     [1024样本 × 1024码本]

  2. 转换为相似度 Q = exp(-D / epsilon)
     epsilon=0.003 (温度参数)

  3. 迭代优化 (100次):
     for iter in range(100):
         # 行归一化: 每个样本的分配概率和=1
         Q = Q / Q.sum(dim=1, keepdim=True)
         
         # 列归一化: 每个码本被分配的样本数相等
         Q = Q / Q.sum(dim=0, keepdim=True) * (1024/1024)

  4. 最终分配:
     样本1 → 码本#12 (概率0.8) + 码本#47 (概率0.2)
     样本2 → 码本#235 (概率0.9) + ...
     样本3 → 码本#891 (概率0.7) + ...

  5. 反向传播时使用软分配的梯度
     前向传播时用硬分配 (argmax)

结果: 
  L1利用率: 100% (所有1024个码本都被使用)
  L1 max_bucket: 216 (最大bucket从9511降到216)


可视化对比:

未使用Sinkhorn:
  Bucket大小分布:
  ██████████████████████████████ 9511样本 (码本#12)
  █ 50样本 (码本#47)
  █ 30样本 (码本#91)
  ... (大量码本未使用)

使用Sinkhorn:
  Bucket大小分布:
  ████ 216样本 (码本#12)
  ████ 205样本 (码本#47)
  ████ 198样本 (码本#91)
  ████ 201样本 (码本#235)
  ... (所有码本均匀使用)
```

## 🎭 硬编码层原理

```
传统L5 (向量量化):

  残差r_4 (64维) → 距离计算 → 256个码本 → 选择最近 → idx_5
  
  优点: 完全数据驱动，语义表达能力强
  缺点: saletype信息可能丢失或不明确

═══════════════════════════════════════════════════════════════════

硬编码L5 (HardCodeMapper):

  不使用残差向量！
  直接从元数据读取 pay_type 字段
  
  映射规则:
    pay_type = "FREE" → saletype = "1" → idx_5 = 49
    pay_type = "PAY"  → saletype = "2" → idx_5 = 42
  
  然后:
    q_5 = codebook[idx_5]  (从码本取出对应向量)

  优点: 
    1. 强制语义分组 (免费和付费严格分开)
    2. 便于业务过滤 (直接看<e_x>就知道付费状态)
    3. 节省码本容量 (只需2-3个码位)
  
  缺点:
    1. L5灵活性降低
    2. 如果saletype分布不均，利用率低
       例: 193034条视频，180000付费，13034免费
            → L5只用了2个码位，利用率 2/256 = 0.78%
    3. 跨域泛化能力弱


实际效果对比:

有硬编码 (RQ-KMeans):
  L1-L4: 向量量化 (4096个语义组合)
  L5: 硬编码 (2种付费状态)
  总SID空间: 4096 × 2 = 8192种
  实际ICR: 98.36%
  L5利用率: 47.8%

无硬编码 (RQ-OPQ):
  L1-L4: 向量量化 (4096个语义组合)
  L5: 向量量化 (512个细分)
  总SID空间: 4096 × 512 = 2,097,152种
  实际ICR: 99.22%
  L5利用率: 100%
```

```

════════════════════════════════════════════════════════════════

   ↓
字段提取 + 规范化
   ↓

   ↓

   ↓

阶段2: 模型训练
════════════════════════════════════════════════════════════════

embeddings.npy
   ↓
训练集/验证集划分 (可选)
   ↓
初始化RQVAE模型
   ├─ KMeans初始化码本 (可选)
   ├─ 配置Sinkhorn参数
   └─ 配置EMA参数
   ↓
训练循环 (10 epochs)
   ├─ Batch: 1024样本
   ├─ Forward: 编码→量化→解码
   ├─ Loss: 重构loss + 承诺loss
   ├─ Backward: 更新编码器/解码器
   ├─ EMA更新码本
   └─ 记录collision rate
   ↓

   ├─ best_loss.pt (最低重构误差)
   └─ best_collision.pt (最低碰撞率)

════════════════════════════════════════════════════════════════

embeddings.npy + checkpoint.pt
   ↓
批量编码 (batch=512)
   ↓
每条生成indices
   ↓
indices.jsonl (193034行)
   每行: {"idx":0, "indices":[12,83,4,701,25], "tokens":[...], "saletype":"2"}


阶段4: SFT数据构造
════════════════════════════════════════════════════════════════

indices.jsonl + train_queries.csv
   ↓
对每个查询:
   ├─ 解析用户query
   ├─ 解析历史对话
   ├─ 找到相关资源ID
   ├─ 查询资源的SID
   └─ 构造训练样本
   ↓
sft_train.jsonl
   每行: {"instruction":"...", "input":"query", "output":"<a_12><b_83>..."}
   ↓
更新 llama-factory/data/dataset_info.json


阶段5: LLM微调
════════════════════════════════════════════════════════════════

基础LLM (LLaMA/Qwen) + sft_train.jsonl
   ↓
LLaMA-Factory LoRA微调
   ├─ Epochs: 3
   ├─ Learning rate: 5e-5
   └─ Batch size: 4
   ↓
微调后的LLM checkpoint


阶段6: 推理和评估
════════════════════════════════════════════════════════════════

test_queries.csv
   ↓
对每个测试query:
   ├─ 加载微调LLM
   ├─ 构建SID Trie (合法SID约束)
   ├─ 生成SID (带Trie约束)
   ├─ 从indices.jsonl反查资源
   └─ 记录预测结果
   ↓
predictions.jsonl
   ↓
评估指标计算
   ├─ Recall@1 (首位命中率)
   ├─ Recall@5 (前5命中率)
   ├─ Recall@10 (前10命中率)
   └─ MRR (平均倒数排名)
```

## 🎓 关键概念速查

### 残差量化 (Residual Quantization)
```
传统VQ: 向量 → 单层量化 → 索引

RQ: 向量 → L1量化 → 残差1 → L2量化 → 残差2 → ...

优势: 多层累积，表达能力指数增长
  1层1024码: 1,024种
  4层1024码: 1,099,511,627,776种 (1万亿+)
```

### Trie约束生成
```
问题: LLM可能生成不存在的SID
  例如: <a_999><b_888><c_777><d_666><e_555>
       (数据集中没有这个组合)

解决: 构建所有合法SID的Trie树

  Trie结构:
    root
      ├─ a_12
      │   ├─ b_83
      │   │   ├─ c_4 ✓
      │   │   └─ c_5 ✓
      │   └─ b_84
      │       └─ c_7 ✓
      └─ a_13
          └─ ...

  生成时:
    当前prefix: "<a_12><b_83>"
    允许next: ["<c_4>", "<c_5>"]
    屏蔽其他: logits[其他token] = -inf

  结果: 保证100%生成合法SID
```
